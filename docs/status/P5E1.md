## 执行上下文

- 服务端按 `DayOccurrence.sequence + ItineraryNode.position` 排序，并结合现有 Node 的 ACTUAL
  ARRIVAL/DEPARTURE 与 confirmed skip 推导当前节点和下一目标；客户端不能指定“当前目标”。
- 目标类型只在执行上下文中轻量区分 `PLACE / TRANSIT_HUB / AIRPORT`。机场身份取当前 Trip 的
  `FlightBinding` 及其最新 snapshot departure IATA；`providerHubRef` 标识 transit hub，其余为 place。
- FreeAction 或其它没有可靠坐标的节点不做自动到达，返回 `MANUAL_CONFIRMATION_AVAILABLE`。

## Arrival、Departure 与定位质量

- 集中 policy 默认值：最大可靠 accuracy `100m`；place/hub/airport arrival radius 分别为
  `75m / 150m / 300m`；exit hysteresis `50m`；departure 至少需要 `2` 个连续可靠样本。
- reliable sample 一旦明确位于当前 target 半径内，立即写 arrival；不要求停留 5 分钟。
- departure 只有在当前节点已有 arrival、尚无 departure、连续位于 exit radius 外、距当前节点增加且
  距下一目标减少时确认。一次跳点或移动方向不符不会产生 departure。
- 绝对 observation 最多允许服务器时间未来 `120s`，最大 age `300s`；明显失序 sample 返回
  `EXECUTION_SAMPLE_STALE`。低质量定位只更新最小状态并返回 `INDETERMINATE_LOCATION`，不生成事实。
- `speedMetersPerSecond` 与 `headingDegrees` 只做输入校验，V1 判定不依赖设备提供它们。

## 持久模型与隐私

- migration `20260924100000_p5e1_execution_location` 增加 `EXECUTION_OBSERVATION`、紧凑
  `ExecutionEvent`、每 Trip 一份 `ExecutionLocationState` 与每 Node 一份 `NodeExecutionState`。
- `ExecutionLocationState` 只保存 last observed instant、当前/目标 node、两项衍生距离、连续离开计数和
  reliable/indeterminate 状态。没有 LocationHistory、GPS Track 或 sample 列表。
- 原始 latitude/longitude、accuracy、speed、heading 和完整 request JSON 计算后丢弃；不写数据库、
  Notification、analytics 或日志，错误也不回显坐标。

## ACTUAL、版本和显式 Undo

- 自动 arrival/departure 写 Node `ACTUAL`，sourceKind 为 `EXECUTION_OBSERVATION`，sourceRef 为
  `execution-event:<eventId>`，instant/observedAt 均使用设备 observation instant。手工确认使用
  `USER_VALUE`，但仍有对应 event。
- 新 arrival、departure、confirmed skip 与成功 Undo 各使 Trip version `+1`。低质量、outside、重复、
  housekeeping 与 possibly-skipped detection 本身不递增版本。
- 已有不同 ACTUAL 不被 GPS 或普通手工操作覆盖。Undo 只有在当前 TemporalValue sourceRef 仍精确属于
  目标 ExecutionEvent 时才删除；Flight/provider 或其它来源 ACTUAL 返回 `FACT_PROTECTED`。
- 同一 logical fact 由 owner lock、Trip row lock、active-event partial unique index 和 source subject unique
  constraint 收口。手工操作与 Undo 使用独立 idempotency key；重放不二次增加 version。

## Skip 与风险

- reliable sample 明确进入后续节点范围时，可以确认该后续节点 arrival，并将其前方尚未到达的节点标为
  `POSSIBLY_SKIPPED`。节点、PLANNED、备注和交通历史均保留。
- 只有显式 `CONFIRM_SKIP` 才变为 `SKIPPED`；撤销该 event 恢复 possible 状态，不删除 itinerary node。
- 每次新增/撤销 ACTUAL 或 confirmed skip 后调用现有 `ExecutionRiskService`；P5E1 不复制 fixed-service、
  protected-time 或 buffer 算法，也不因偏离路线本身制造 warning。

## Airport / P5D3 integration

- Airport arrival 的 ACTUAL 先在 PostgreSQL transaction 中提交，再在事务外用服务器推导的 IATA 调用
  P5D3 `ARRIVED_AT_AIRPORT`。Provider HTTP 不进入 execution fact transaction。
- `airportTriggerClaimedAt + airportTriggerClaimToken` 构成 PostgreSQL 持久 claim lease；同一 arrival event
  的普通并发 reconciliation 只有一个 caller 能调用 P5D3。Provider 调用仍在 claim transaction 提交后执行。
- `airportTriggerCompletedAt` 是完成 marker。明确失败会按 claim token 释放 claim，后续同一 observation、手工
  replay 或 reconciliation 可以重试；Undo 会清除 claim，undone event 永远不可再次领取。
- 默认 claim lease 为 120 秒。若 Provider 已成功但进程在写 completed marker 前崩溃，lease 到期后允许
  at-least-once 重试；当前数据不足以无歧义证明远端 refresh 已完成，因此不宣称 crash window exactly-once。
  正常并发仍由行锁、claim token 与 lease 严格收口为单次 Provider 调用。
- 到达机场只表示 `ARRIVED_AT_AIRPORT`；不推断 check-in、security、gate arrival 或 boarding。

## Active Trip 边界

- `/trips/:tripId/execution/location` 明确表示 caller 已选择正在执行的 Trip；服务端只在该 owner-scoped Trip
  内推导当前节点。未来 native background location 必须先选择 active Trip，再向该 endpoint 提交位置。
- P5E1 不增加全局 `ExecutionSession`，也不允许后台定位把同一 observation 广播到多个 Trip。

## API

- `POST /trips/:tripId/execution/location`
- `POST /trips/:tripId/execution/events`：`MANUAL_ARRIVAL / MANUAL_DEPARTURE / CONFIRM_SKIP`
- `POST /trips/:tripId/execution/events/:eventId/undo`
- `GET /trips/:tripId/execution`

全部为 owner-only private resource；ADMIN 没有跨 owner 例外。GET 只返回 frontier、最近 execution facts、
skip 状态、定位质量与 active risk，不返回位置历史。

## 非目标

- 不实现 iOS/Android 权限、OS background location、持续轨迹、breadcrumb map、speed history、
  off-route alert、Push、正式 Desktop/Mobile UI、“已上车/已登机”判断、missed train/next train、自动改路线/
  时间或 Staging/Production enablement。
