## 实现范围

- 新增 provider-neutral `FlightSnapshotProvider.search/refresh` 端口和 AeroDataBox RapidAPI 服务端适配器。
- 新增 owner/Trip/TransportEdge 强关联的 `FlightBinding`；一条当前 TransportEdge 最多一个绑定。
- 航班 adopt 要求已有 `mode=FLIGHT` 的 TransportEdge，写入固定班次标识与起降
  `PLANNED` 事实。相同航班和计划事实重放不增加 Trip version。
- 手工 refresh 精确匹配 candidate ID；ID 改变时只允许航班号、service date、起降机场与
  计划起飞时刻唯一全匹配，否则返回 `FLIGHT_NOT_FOUND / FLIGHT_AMBIGUOUS`。
- revised 映射为 `ESTIMATED`，runway 映射为 `ACTUAL`，predicted 不映射 TemporalValue。已有不同
  ACTUAL 不覆盖，在刷新结果中显式返回 conflict。
- 航班状态、运行时间、gate、terminal、baggage 和 aircraft 以结构化 change summary 返回。
  `CANCELLED / DIVERTED` 只标记 attention/re-evaluation，不自动删除、换班或重排。

## 配置与安全

- 默认 `FLIGHT_PROVIDER=unconfigured`、`FLIGHT_LIVE_API_ENABLED=false`。只有 provider 为
  `aerodatabox`、live flag 为 true 且服务端存在 key 时才发起网络请求。
- key 优先级为 `AERODATABOX_RAPIDAPI_KEY` 高于 `RAPIDAPI_KEY`；key 不进入 Git、数据库、快照或日志。
- search 可使用内存短缓存；手工 refresh 始终 bypass cache。
