# 可复核证据矩阵

本文件的代码定位均以业务固定基线 `317a08ed4c9d5ff0fcb455573a012762269eaaf7` 为准。审计分支新增的测试以 `[AUDIT ...]` 名称明确标识，只刻画基线行为，不修复业务。

状态含义：

- `BASELINE_TESTS_PASSED`：固定基线的既有断言在 main CI 通过。
- `STATIC_CONFIRMED`：调用链与分支可由固定 SHA 直接确认。
- `DEFECT_REPRODUCED`：审计新增的隔离 PostgreSQL/Domain 用例实际复现缺陷。
- `UNVERIFIED`：没有足够动态证据；不据此宣称正确或缺陷。
- `NOT_IMPLEMENTED`：链路所需能力在基线不存在。

## 重点问题结论

### P3 / P5C

1. **SystemDwellSuggestion 没有升级成用户硬要求。** `schedule-propagator` 的 hard basis 不读取 suggestion；`RouteQueryService` 仅在没有 user MIN 时用 suggestion 计算 planning start/lookback。suggestion 与 user MIN 可并存且独立删除。`STATIC_CONFIRMED`。
2. **最早到达排序是通过硬约束和 adjustment 分池后的 fallback，不覆盖明确用户约束。** provider candidate 先按 hard earliest/latest 二次过滤，再优先对无需修改 USER MIN 的候选排名；需要 adjustment 的候选仍可见但不会压过 fully-feasible primary pool。`STATIC_CONFIRMED + BASELINE_TESTS_PASSED`。
3. **三类 buffer 没有混用。** `SYSTEM_SUGGESTED_BUFFER`、`USER_PREFERRED_BUFFER`、`SYSTEM_MINIMUM_CONNECTION` 的 disposition/ack 规则有独立 unit assertions；minimum UNKNOWN 不猜。参照点仍需由后续真实 provider/client 数据保证，非当前 bug。

### P3 / P5D1

1. fixedService Transport 的 PLANNED 时刻作为不可平移 hard anchor；Transport ACTUAL 无论 fixed 与否都是事实 anchor。
2. 这些 anchor 不创建、锁定或改写 `UserTimeIntent`，因此没有进一步变成“用户不可放弃的承诺”。用户承诺仅来自明确 intent/lock。保持班次时间真实本身不是问题。

### P5D1 / P5D3

同一次 `FlightService.refresh` 会先调用 ExecutionRisk 评估（可能创建 `EXECUTION_RISK`），随后 Flight monitor commit 可创建 `FLIGHT_IMPORTANT_CHANGE`。两者 dedupe key 和 kind 不同，没有跨域 aggregation/suppression。审计 PostgreSQL 用例明确断言一轮 refresh 后各一条，见 F-12。

### 安全入口

owner 校验与来源可信性是两件事。`POST /trips/:id/temporal-values` 正确隐藏跨 owner Trip，但同一个普通 owner 可提交 `sourceKind=PROVIDER_OBSERVATION` 与任意 `sourceRef`；审计 PostgreSQL 用例实际接受并持久化。该入口没有证明调用者是受信 Provider adapter，见 F-11。
