# 模型与推理强度建议｜每次开发要求必填
**核实日期：2026-09-17。以下是任务级工程建议，不是任何模型完成正确性的保证。**

## 1. 本次核实
OpenAI官方模型页列出了GPT-5.6 Luna、Sol；两者API reasoning effort均支持包括high、xhigh、max的档位。官方使用指导把Luna用于清楚、可重复任务，Sol用于复杂工作。[S01][S02][S03]

**客户端差异必须保留：** API支持max不代表每个Codex版本都可直接写`model_reasoning_effort="max"`。本次配置参考页枚举仍列至xhigh，而模型使用页说明Max可在支持客户端中选择。因此本包不自动改用户全局Codex配置，也不把Max与xhigh认成同一个枚举。开工核对实际模型选择器/CLI版本。[S03][S11]

## 2. 本次首选
**首次P0：GPT-5.6 Sol + Extra High（xhigh）。**
原因：空白项目需要把多终端、鉴权、任务、时间来源、数据隔离与阶段边界一次整理清楚；这比“照现成规格写一个函数”更需要架构判断。

**备选：GPT-5.6 Luna + Max（仅在客户端提供时使用）。**
可以用于明确的工程初始化、CRUD、测试补充；拆小任务，架构/安全/时间模型另做独立审查。不能把“可用”写成“必然足够”。

## 3. 阶段推荐
| 任务 | 推荐模型 | 强度 | 升级/复核条件 |
|---|---|---|---|
| P0 蓝图与空白项目初始化 | GPT-5.6 Sol | Extra High / xhigh | 跨模块模型冲突未解时停止提问，不靠继续加大推理猜需求 |
| P1 认证、会话、隔离 | GPT-5.6 Sol | Extra High / xhigh | 权限绕过/并发token消费必须独立安全审查 |
| 明确CRUD、配置、文档、测试代码 | GPT-5.6 Luna | Max（若可用） | 连续两轮同类失败或改动范围扩大，换Sol审查并缩小任务 |
| P2/P3 领域、双向排程 | GPT-5.6 Sol | Extra High / xhigh | 时区/循环传播/约束冲突难题可单独Max |
| P4 事务、幂等、Provider边界 | GPT-5.6 Sol | Extra High / xhigh | DB并发、过期预览、外部副作用重点复核 |
| P5 薄测试UI、补充测试 | GPT-5.6 Luna | Max（若可用） | 涉及新产品选择回到产品确认，不放任模型自定 |
| 合并前独立代码审查 | GPT-5.6 Sol | Extra High / xhigh | 与实现任务分开上下文，仅基于PR与验收证据 |

不默认开Ultra/多代理并发，不因模型更强就扩大阶段范围。当前已有模型能够承担分段工作，无需为了开工强制更换最高档产品；更换建议必须基于实际任务与测试表现。

## 4. 以后每次任务头部固定格式
```text
推荐模型：<实际可用模型名称>
推荐推理强度：<界面名称；已确认时附参数名>
备选：<成本/速度方案；需怎样复核>
选择理由：<该任务的风险与复杂度>
升级条件：<何时换更强模型或拆小>
本次阶段：<仅一个阶段>
```

发出任务前核实模型可用性；不能机械永久沿用今天名称。发给Codex的文字不会自动改变正在运行的模型；用户应在客户端选择。模型无法自证当前配置时汇报“未能确认”，不得声称已切换。

官方来源仅支持模型与档位事实，具体P0～P5分配是本项目工程判断。验收以代码、测试、PR为准，不以模型名称为准。
