## NotificationEvent

- PostgreSQL 持久化 owner、kind、dedupeKey、用户可见 title/body、occurredAt、createdAt 与
  dismissedAt；`(ownerUserId, dedupeKey)` 唯一约束保证同一用户逻辑事件幂等。
- `GET /notifications` 认证后只返回 actor 自己的数据，按 `createdAt + id` 稳定倒序游标分页；
  已 dismiss 的记录默认仍返回并携带 `dismissedAt`。
- `POST /notifications/:id/dismiss` owner-only 且幂等。ADMIN 不能读取或 dismiss 其他用户事件。
- 创建只开放给可信 application / worker 用例，没有公开 `POST /notifications`；本阶段不发明
  风险语义、不实现 Push、偏好或正式 UI。

## ObjectStorage 与 StoredObject

- `packages/storage` 提供流式 `put/open/delete/stat/exists` port；Local Filesystem adapter 仅供
  Development/Test，未来 provider 可替换而不改变 application 契约。
- `StoredObject` 只保存 owner、服务端随机 key、PENDING/READY/FAILED/DELETED 状态、展示元数据、
  实际 byte size 与 SHA-256；数据库不存二进制，P2 前不关联虚假 Trip。
- Local adapter 限定隔离 root 与 UUID key，拒绝 traversal、绝对/编码路径和 symlink；先写私有
  temporary file，校验实际大小/hash 后 atomic rename，失败清理且不标 READY。
- owner 取自认证 actor，ADMIN 无跨用户能力；READY 才可读，DELETED 不可读，删除可重试且幂等。
- 单文件大小、用户总量和 MIME allowlist 均来自环境配置。总量预留通过 PostgreSQL owner 级
  advisory transaction lock 串行化，防止并发明显超卖。
- O-09 正式产品数值仍待上线阶段确认。Development/Test 的 10 MiB/100 MiB 默认值仅为
  SYNTHETIC 工程默认；Staging/Production 必须显式配置且真实 provider 未实现时保持不可用。
