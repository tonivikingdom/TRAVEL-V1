## 实现边界

- 新增 `RouteProvider` application port 与 `POST /trips/:id/routes/query`。
- Query 校验 owner、basisVersion、当前 adjacency 与两个 PLACE_VISIT 端点；FreeAction 不被伪造为静态地点。
- 查询直接复用 P3B2 evaluation/propagation，使用 from DEPARTURE earliest 与 to ARRIVAL latest。
- 一次性 DEPART_AT/ARRIVE_BY hint 使用严格 absolute instant + IANA timeZone，只进一步收紧 hard window；
  不写 UserTimeIntent、TemporalValue、TransportEdge、DayOccurrence 或 Trip version。
- normalized RouteCandidate 保留 provider/observedAt/ref、查询 basisVersion/时间条件、overall、multi-leg、
  walking、独立 fixedService、nullable fare。Candidate 与 TransportEdge 不等价。
- Application 不信任 Provider：再次检查 hard window、time zone、duration 与 candidate ID；全部越界返回
  `NO_MATCHING_CANDIDATE`，与 `PROVIDER_UNAVAILABLE`、`UNSUPPORTED_QUERY` 明确区分。

## Provider 安全边界

- P4A1 仅提供可配置的 `SyntheticRouteProvider` 和明确失败的 `UnconfiguredRouteProvider`。
- Development/Test 必须显式配置 `ROUTE_PROVIDER=synthetic` 才启用测试候选。
- Staging/Production 禁止 synthetic；真实 Provider 未接入时返回
  `ROUTE_PROVIDER_UNCONFIGURED`，不存在静默 synthetic fallback。

## Schema / migration

P4A1 本身未新增数据库表、字段或 migration；合并时 RouteCandidate 仍是指定 Trip `basisVersion` 上的
一次性查询响应。P4B1 现已单独获授权，在新的 feature 分支中增加短期服务端快照与 Preview，不改写
P4A1 已确认的 Provider-neutral Query 语义。

## 明确未实现
