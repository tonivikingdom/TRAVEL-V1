## Storage and architecture

The existing ObjectStorage interface has private local filesystem put/open/stat/delete and StoredObject metadata, quotas and durable cleanup. It is an upload/file abstraction; no Attachment domain model, Trip export or versioned backup association exists. RouteCandidateSnapshot/Preview and FlightBinding snapshots are planning/Provider evidence, rather than personal Trip backup artifacts. The formal Web hides stale live data during core failure; it had no offline Trip cache or service worker.

**Decision: bounded structured JSONB in PostgreSQL.** TripStaticBackup stores id, ownerUserId, tripId, tripVersion, generatedAt, idempotencyKey and artifact. The composite FK references the exact Trip/owner pair and cascades on Trip deletion. Unique owner/Trip/key supports replay. Owner/Trip/generation/id index supports latest read. Artifacts are append-only through the application; no update, overwrite or delete endpoint exists. A later explicit generation creates another artifact, preserving earlier rows. Only the latest artifact is exposed by this batch.

One new migration: `20261003100000_p6b2_static_backup`. Historical migrations unchanged; **26 total**. The existing 25-migration authoring test now explicitly selects its original historical boundary, as the storage migration tests already do. Separate new tests deploy all 26 cleanly and apply populated 25→26, comparing every pre-existing table without dropping assertions. No dependency/lockfile/CI/Compose configuration changes.

The application and database bound each artifact to 1 MiB. PostgreSQL performs the itinerary/adoption evidence read, FlightBinding read and backup insert inside one **REPEATABLE READ** transaction. The request supplies the version the user reviewed. A stale starting version returns VERSION_CONFLICT. A concurrent update after the first read is never mixed into later reads; PostgreSQL serialization rejection at the composite FK is mapped to VERSION_CONFLICT with full rollback. The deterministic actual-PG test pauses between aggregate and Flight reads, commits N+1 from another device, observes conflict/zero artifact, then explicitly retries at N+1. A stable transaction generates a complete N artifact.

Same owner/Trip/key replays the original artifact even after live editing, before checking the later live version. Reusing that key with another base version returns IDEMPOTENCY_CONFLICT. Concurrent duplicate generation handles unique-key contention by fetching the accepted original artifact; the real-PG test verifies identical responses and one row. Reads/generation never update Trip.version, dates, nodes, execution events, authoring/route receipts, Query/Preview/Adopt/Undo or Provider state.

## API and privacy

- `GET /trips/:tripId/backup` → `{ backup: StaticBackupView | null }`; an owned Trip without backup returns null. A foreign owner/admin receives 404.
- `POST /trips/:tripId/backup` → immutable `StaticBackupView`; body `{ baseTripVersion, idempotencyKey }`. Explicit user action only. Validation, current session and owner-private authorization use existing infrastructure.
- Successful responses use `Cache-Control: private, no-store`. No anonymous/shared URL or Provider call.

`travel-static-backup-v1` is a separate read-only contract. It includes Trip ID/version, artifact ID/generation time, name, people count, effective range, DayOccurrence IDs/sequence/dates, nodes in itinerary order, known place name/address/coordinates, notes, original planned times, independently saved user time requirements/minimum dwell, selected transport summary, saved legs with boarding/alighting and endpoint timezones, and eligible Flight selected/saved snapshots.

Projection is field-by-field: never serialize an aggregate or spread raw stored Provider JSON. Flight data keeps flight number/service date, fetchedAt and whitelisted scheduled/revised/predicted/runway/airport/terminal/gate/baggage fields. It omits raw status/response, candidate/provider reference identities, aircraft identifiers, auth/user/email/session/credential/token data, execution locations, internal receipts and unnecessary private metadata. Extra nested credential-like fields injected into saved Provider JSON are excluded by the real-PG test. Unknown addresses, coordinates and times remain unknown. User-written notes are intentionally private content included by this explicit action; no OCR, natural-language parsing or secret classification of notes is performed.

No object uploads, S3 system, virus scanner, OCR or document classifier. No accommodation classification is manufactured.

## Live versus backup behavior

The existing Trip page keeps Today/Next, itinerary and authoring. A quiet secondary “旅行资料 / 备份” entry opens online facts. Flight evidence must match the owned Trip version; denial/version disagreement conceals the current projection. Viewing does not generate or persist a backup. Provider failure remains local to those fields.

Only “更新离线备份” sends POST. After acceptance, the browser stores this **explicit static artifact**, keyed by verified owner/Trip, without auth credentials. There is no saved Live Trip, auto-generation on open/evaluation/refresh, polling, background sync, offline editing or service worker. Unknown network outcomes retry the same key/body/version; definitive conflicts require fresh live data. Server generation success with failed local storage reports that distinction and offers file download.

The static reader says “正在查看备份”, “备份生成于 …”, Trip version and “此内容不会自动更新”. If a later live version is known, the difference is explicit. If core service is unavailable, it says the online version cannot be verified. “保存时预计” and saved Flight timestamps describe history; no latest Provider status becomes a present-tense guarantee. Static viewing opens no maps/Provider queries and offers no authoring controls.

Core unavailable/offline hides live data and offers “查看最近备份” when this owner has an explicitly saved local artifact. Without one it says “暂无可用备份”, specifies that this browser has no copy and that the server can be checked after recovery. Failed reads do not keep a “正在读取” indicator. A prior verified session's owner binding supports same-tab reload when `/me` is temporarily unavailable; a successfully verified different owner clears the prior owner's copies. Explicit logout clears copies/binding even when the logout request fails. Damaged local artifacts are ignored. No administrator exception exists. Today clock ticks do not rerender an open static reader or collapse expanded saved legs.

**Independent emergency file:** “下载静态文件” exports escaped, script-free, self-contained HTML from an existing accepted artifact. CSP blocks scripts/external resources. It includes no session credential and opens with no API/network requests; expandable saved route/Flight details remain readable. This covers leaving the webpage without creating an offline application shell. Files contain personal notes and must be kept privately; the UI explains this before generation. Downloaded files cannot be remotely revoked or erased by logout.
