## 补偿语义与版本

- Undo 是一次新的 forward compensation transaction，不是数据库快照回滚。Adopt 从 v12 到 v13，
  Undo 成功后是 v14，不会倒退到 v12。
- 只允许撤销 Trip 当前版本所对应的最近一次可撤销 Route Adopt。target receipt、request
  `baseTripVersion` 与当前 Trip version 必须完全匹配；Adopt 后任何其他正式写入都会返回
  `UNDO_CONFLICT`。
- Undo-of-Undo、Redo、多级历史栈、非 Route Adopt command 的 Undo 均不在本阶段。

## 完整 inverse basis

- 所有新 Adopt receipt 使用 `route-adopt-delta-v2`，在事务开始前保存整趟 Trip 的
  DayOccurrence identity/date/sequence、所有 Node placement、corridor 内 generated Node 完整可逆元数据、
  beforeOwnedDates、effective range、prior ACTIVE route，以及本次创建的 Place/DayOccurrence IDs。
- 历史 P4B2 receipt 不伪造 inverse data，`undoExpiresAt=null`；请求 Undo 时返回
  `UNDO_UNAVAILABLE`，禁止根据名称、Provider ref 或当前数据库状态 best-effort 猜测。
- Undo receipt 使用独立 `route-undo-delta-v1` 并通过 `targetOperationReceiptId` 唯一引用被撤销的
  ROUTE_ADOPT receipt。

## Undo window、并发与幂等

- 新 Adopt receipt 在创建时固定写入 `undoExpiresAt`。Development/Test 默认
  `ROUTE_UNDO_WINDOW_SECONDS=600`；Staging/Production 必须显式配置。600 秒是可配置工程默认，
  不是永久产品承诺。
- owner advisory transaction lock + Trip `FOR UPDATE` + `READ COMMITTED` 与 Adopt 共用同一序列化边界。
- 幂等查找发生在 Trip/version 校验之前：同 key/同 request hash 返回原 Undo receipt，不重复增加
  version、receipt 或 outbox；同 key/不同 target/version 返回 `IDEMPOTENCY_CONFLICT`。
- 同一 target receipt 由数据库 unique constraint 保证最多一份 Undo receipt。

## 生命周期与安全恢复

- `AdoptedRoute` 生命周期为 `ACTIVE / REPLACED / UNDONE`。Undo replacement 时先把 target
  ACTIVE route 标为 UNDONE，再将 receipt 明确记录的 prior REPLACED route 恢复 ACTIVE。
- PostgreSQL partial unique index 保证同一 Trip/anchors 最多一个 ACTIVE route。Adopt transaction
  先将 prior ACTIVE 标为 REPLACED，再创建新 ACTIVE；任何后续失败由事务整体回滚。
- Undo 必须重新验证当前 corridor、generated Node/Edge identity、History、route lifecycle 与完整
  after topology。任何漂移返回 `UNDO_CONFLICT`，不自动修复。
- target-created Node/Edge 出现 ACTUAL，generated Node 出现新 note、UserTimeIntent、用户修改或未知
  引用时，Undo 拒绝。P4B3 不把新事实搬回旧路线。
- 原 DayOccurrence 用原 ID、localDate、sequence 恢复；Node 依据保存的 dayOccurrenceId/position 恢复，
  不按 localDate 重排。DateOwnership 严格恢复 `beforeOwnedDates`；若已由同 owner 的另一 Trip 合法占用，
  整个事务返回 `UNDO_CONFLICT` 并回滚。
- 被替换 TransportEdge 使用原 ID、强类型时间事实和 DayProjection 恢复；临时 USER_REPLACED History
  在成功恢复后删除。OperationReceipt 和 outbox 仍记录“曾 Adopt，随后 Undo”的审计事实。

## API 与 outbox

- `POST /trips/:id/operations/:operationReceiptId/undo` 只接受
  `baseTripVersion + idempotencyKey`；客户端不能上传 before state、route、node、edge 或 delta。
- 成功写入 ROUTE_UNDO receipt 与 `ROUTE_UNDONE` outbox，均与 topology、route lifecycle、
  DateOwnership/effective range 和 Trip version +1 位于同一 PostgreSQL transaction。
- 公开错误：`UNDO_CONFLICT`、`UNDO_EXPIRED`、`UNDO_UNAVAILABLE` 均为 HTTP 409；跨 owner target
  继续统一 NOT_FOUND。
