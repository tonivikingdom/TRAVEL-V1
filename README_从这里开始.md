# 旅途计划｜首轮开发要求与 Codex 指令包
**开发要求版本：v1.0　产品基线：v0.6　导出日期：2026-09-17**

> 当前是一个**新建空白项目**，不是旧仓库改造。本包是开发规格与交接资料，不是已经实现或测试通过的软件。

## 现在怎么用
1. 将本包解压到你确认的新项目工作目录，保留目录结构。不要覆盖另一个项目已有的 AGENTS.md。
2. 在 Codex 中打开包含 `AGENTS.md` 的那一级项目目录，不要打开外层下载目录。第一次只发送 `prompts/00_首次开发_空白项目初始化.md` 的完整内容。
3. **推荐模型：GPT-5.6 Sol；推理强度：Extra High（xhigh）。** 成本优先备选：GPT-5.6 Luna / Max；核心模型设计必须另做复核。实际选项以当前客户端为准。
4. Codex 完成 P0 后必须提交、推送到新仓库功能分支并创建 PR，交回测试结果。检查通过、你同意后，才执行下一阶段。

**不要一次把 P0～P5 全部交给 Codex 自动连续开发。** 完整产品蓝图不等于本轮任务清单。

## 新仓库尚未指定
新 GitHub 仓库地址尚未提供。本包不会猜测地址，也没有向任何仓库上传。

Codex 开始时须检查本地 `origin`；若没有远程地址或无法确认归属，只询问**新仓库地址**。禁止自动将旧仓库 `tonivikingdom/travel-planner-v2` 设为目标。

如果新 GitHub 仓库还没有 `main` 的任何提交，需要先建立一个仅含 README / .gitignore 的初始基线，才能正常做功能分支 PR。**这一步必须由用户完成，或获得单独的初始化授权；不能借此直接向 main 提交业务代码。**

## 本轮部署目标
现有 x86-64 电脑（用户提供：i7-12700 / 32GB），同时在线不超过5人；先 Dev + Staging，只有测试数据。Web/API 与 Worker 独立进程，同机 Docker Compose；PostgreSQL；附件对象存储；受控邀请制、Magic Link、可撤销会话、多账号隔离。

**首轮不等于全功能 App。** 不做正式桌面/移动 UI，不打包 Windows/macOS/iOS/Android，不做同行协作、公开注册、原生 Push、天气、预算、OCR、完整审计或自动异地灾备。

## 交接方式
每个阶段都使用 feature branch → 测试 → commit → push → PR → 检查 → 用户同意后合并 main。任何失败、缺权限、缺服务、未运行测试都要原样报告，不得声称完成。

规则有矛盾时：先看 `docs/00_需求优先级与变更记录.md`；未决项按 `docs/08_未决事项与阶段闸门.md` 处理。只暂停相关能力，不用旧逻辑或猜测填补。
