# 字段与事实来源

旅行时间、状态与来源不能压成一组可互相覆盖的字段。后续数据模型必须至少保留
以下四类信息：

| 类别            | 含义                                      | 可否由重算覆盖                                       | 典型来源                         |
| --------------- | ----------------------------------------- | ---------------------------------------------------- | -------------------------------- |
| 用户目标 / 约束 | 用户希望、必须、最早/最晚、最低停留等意图 | 否；只能由获授权的用户动作修改                       | 用户命令、结构化确认             |
| 已采用方案      | 用户明确 Adopt 后的路线/排程快照          | 不能被 Query/Preview 修改；新 Adopt 通过版本事务替换 | Adopt 回执、Provider 快照        |
| 当前预计        | 基于当前版本与最新证据推导的可失效结果    | 可以重算，但必须保留来源、新鲜度和策略版本           | ScheduleProjection、Evidence     |
| 实际事实        | 已确认发生的到达、离开、执行状态          | 不能被自动排程回写或删除                             | 用户确认、授权设备证据、受信来源 |

时间值至少需要本地日期时间、IANA 时区、可确定时的 instant、sourceKind、
sourceRef、observedAt 与 quality。持续时长按 instant 计算，不使用服务器默认时区
解释用户输入。无法消除夏令时或日期线歧义时返回明确错误，不静默“修正”。

## 不可混淆的例子

用户把到达目标改为 19:30，但当前已采用交通预计 19:56 到达时：

- 19:30 仍是用户目标；
- 19:56 仍是当前已采用方案支持的预计；
- 系统产生冲突解释，而不是把任一值覆盖掉；
- 没有实际证据时，不产生 Actual。

P0 的 `deriveMinimumArrival` 只是验证 domain 可脱离 I/O 且输出规则/来源。它接收
已解析 instant，不实现 O-03 所涉及的本地时间歧义或高级日期投影。
