## 已完成

- 建立 Node 24 / pnpm 11 / TypeScript strict workspace，并生成锁文件。
- 建立 `api`、`worker`、`domain`、`contracts`、`persistence` 的 P0 必要边界。
- API 只提供 `/health/live` 与 `/health/ready`；readiness 执行真实 PostgreSQL
  `SELECT 1`，连接缺失或失败时返回 503。
- Worker 独立启动，周期探测 PostgreSQL、写健康文件，并处理 `SIGINT` /
  `SIGTERM` 优雅停止；尚无业务任务或通知。
- Dev / Staging Compose 使用不同项目名、端口、数据库与命名卷，宿主机只绑定
  `127.0.0.1`；Production 只有禁用部署的配置形状。
- CI 包含格式、lint、typecheck、unit、真实 PostgreSQL integration、build，以及独立
  Compose 镜像/运行/故障恢复/持久化验证。
- R1：PostgreSQL Pool 注册后台 `error` 处理，查询与连接有界超时，日志只保留错误名；
  受控终止空闲连接后可恢复探测。
- R2：Worker 运行/停止控制器处理启动竞态、重复停止、在途探测超时和 SIGTERM；停止后
  不注册新定时器或心跳。
- R3：minimum-arrival 只接受带 `Z` 或显式 UTC offset 的严格 ISO 绝对时刻。
- 架构文档区分用户意图、已采用方案、当前预计与实际事实，并登记权限、Job、
  Trip 版本、Query/Preview/Adopt 责任和 P1～P5 闸门。
- 发现 TypeScript 7.0.2 与 typescript-eslint 8.70.0 不兼容后，固定到已核验的
  TypeScript 6.0.3；没有关闭 lint 或降低规则。
