## 实现范围

- Route Query 在 Provider I/O 完成后进入短事务，重新锁定 Trip 并复核版本、owner 和 occurrence-sequence
  adjacency，随后保存服务器拥有的 immutable `RouteCandidateSnapshot`。
- Snapshot 保存 normalized candidate（不保存第三方 raw JSON）、provider provenance、查询时间条件、稳定
  SHA-256 candidateHash、内部 TTL 和不晚于 provider validity 的 expiry。
- `POST /trips/:id/previews` 只接受 `basisVersion + candidateSnapshotId`；重新校验 owner、Trip version、
  snapshot expiry/hash/domain、当前 PLACE adjacency 和 P3B2 hard requirement window，不重新调用 Provider。
- immutable `RoutePreview` 保存 `route-adoption-preview-v1` 输出：当前连接、CREATE/REPLACE、候选、潜在
  transfer points 和 proposed segments。多 leg continuity 不按名称猜测，必需 transfer 必须具有坐标。
- `GET /trips/:id/previews/:previewId` 维持 owner isolation；过期 Preview 返回 `status=EXPIRED` 且
  `adoptable=false`。

## 不变量

- Query/Preview 不增加 Trip version，不修改 Place、ItineraryNode、TransportEdge、TemporalValue、
  UserTimeIntent、DateOwnership、TransportHistory 或 Notification。
- Preview 不创建实际 transfer Node，不归档现有 Transport，不复制 Transport 时间到 Node；未来 Adopt 后的
  候选时间只允许成为 `PLANNED + ADOPTED_TRANSPORT_FACT`，绝不伪装为 ACTUAL。
- walking 与 fixedService 使用 normalized candidate 的明确值，不能从 mode 推断。
- Snapshot/Preview 的 expiresAt 均有索引；本轮正确性依赖读取/创建时 expiry 检查，暂不扩大 Worker cleanup。
