## 实现边界

- 纯 domain propagator 为每个 Node 的 ARRIVAL/DEPARTURE 计算 earliest/latest requirement window。
- 所有 UserTimeIntent、Node/Transport ACTUAL、fixedService Transport PLANNED 是 hard basis。
  Node PLANNED/ESTIMATED、非固定 Transport PLANNED 与 Transport ESTIMATED 不参与硬传播。
- MIN_DWELL 支持 forward/backward/bidirectional 单调收紧；没有锚点时保持 UNBOUNDED。
- worklist 在 bound 不再收紧时到达 fixed point，并有有界 relaxation guard；每个 bound 带结构化
  ruleId、sourceRefs 与简短解释。lower > upper 返回 `PROPAGATION_BOUND_CONFLICT`，ACTUAL 不改写。
- 现有 `POST /trips/:id/schedule/evaluate` 增加 requirementWindow 并继续保持 read-only；P3B1 的
  current-value evaluation 与 propagated requirement 不混为同一个时间事实。
